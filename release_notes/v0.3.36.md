This release gets the engine ready for the app to sync account keys through iCloud Keychain. Generating or importing a key no longer silently replaces a different key synced through iCloud Keychain. A new `exportKeypair()` returns the recovery phrase from memory. Existing callers compile unchanged, but anyone implementing the bingle_local traits must add code.

## What changed

Two of the three pull requests change what an integrator sees, and both concern key handling.

| Area | Change | Issue |
|---|---|---|
| App bridge (bingle_jsi) | `generateKeypair` and `importKeypair` now reject instead of replacing a different key synced through iCloud Keychain. The error, `SyncedKeyWouldBeReplaced`, carries the stored address. Once the user agrees, call `generateKeypairReplacing` or `importKeypairReplacing` to replace it. | [#452](https://github.com/binglefoundation/bingle_rust/issues/452) |
| App bridge (bingle_jsi) | New `exportKeypair()` returns the current keypair's address and recovery phrase from memory. It works with the Keychain store and with the sealed state file, where the phrase can no longer be read from the file. With no keypair it fails with `InvalidRequest`. | [#466](https://github.com/binglefoundation/bingle_rust/issues/466) |
| Local library | `generate_keypair()` and `import_keypair(passphrase)` refuse to replace a different synced key and return `BingleError::SyncedKeyWouldBeReplaced`, changing nothing. New `generate_keypair_replacing` and `import_keypair_replacing` replace it when asked. Device-only keys, the same key again, handle clash recovery and opening a restored state file are unaffected. | [#452](https://github.com/binglefoundation/bingle_rust/issues/452) |
| Release process | The 0.3.35 post-release checks both passed, so their entries are removed. The list of post-release checks is now empty. | [#465](https://github.com/binglefoundation/bingle_rust/issues/465) |

## Upgrading

Existing callers compile unchanged, but trait implementors must add code, and apps should handle the new refusal.

- **App (React Native):** handle a `SyncedKeyWouldBeReplaced` rejection from `generateKeypair` and `importKeypair`. Warn the user, then retry with `generateKeypairReplacing(true)` or `importKeypairReplacing(passphrase, true)`. On iOS the rejection message is `SyncedKeyWouldBeReplaced(storedAddress: "…")`. To read the recovery phrase, use `exportKeypair()` instead of reading `keypair.passphrase` from a saved state file.
- **Rust users of bingle_local:** implementors of `BingleLocalApi` must add `generate_keypair_replacing` and `import_keypair_replacing`. `KeyStore::store` gains `replace_synced: bool`, and `BingleApiLocalImpl::import_keypair_shared` gains `replace_synced_key: bool`. `KeyStoreError` gains `WouldReplaceSyncedKey`, and `BingleError` gains `SyncedKeyWouldBeReplaced`.
