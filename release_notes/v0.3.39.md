v0.3.39 adds the global blocklist for App Store guideline 1.2. A moderator can block an account on chain, and the app can then drop that account's messages. Nothing breaks, because the app only drops these messages once it turns on `enable_global_block`. Relays and clients now also drop relay-only messages from senders that lack the on-chain `allow_relay` flag.

## What changed

Four changes are visible to users or integrators: the global blocklist in the app and local library, the new `blocked_user` bit, the relay-only message check and the chat help text.

| Area | Change | Issue |
| --- | --- | --- |
| App bridge (bingle_jsi) | New `enable_global_block` option in `BingleJsiConfig`, off by default. When it is on, a live message from a sender a moderator has blocked is dropped before it is stored or shown. A new block takes effect within the handle cache expiry, which is 600 seconds by default. | [#504](https://github.com/binglefoundation/bingle_rust/issues/504) |
| Chat CLI | `bingle_cli chat --help` and the top-level usage now list `--poll-interval <secs>`. With `--store-forward receive` or `both`, the Mailbox is read on start and then every `<secs>` seconds. The default is 20, and 0 reads it on start only. | [#484](https://github.com/binglefoundation/bingle_rust/issues/484) |
| Core library | The decentralised application (DApp) contract has a new `blocked_user` bit that only an admin can set, with `set_blocked_user`. bingle_core adds `AlgoBingle::set_blocked_user`, `AlgoBingle::check_blocked_user` and `AlgoBingle::account_standing`. Nothing on chain is refused to a blocked account: clients enforce the block, and it survives an app migration. | [#503](https://github.com/binglefoundation/bingle_rust/issues/503) [#504](https://github.com/binglefoundation/bingle_rust/issues/504) |
| Core library | The engine now drops relay-only message types, such as triangle tests 2 and 3 and RelayCalled, if the sender lacks the on-chain `allow_relay` flag. Each engine caches the answers. If the check cannot be made, the message is dropped. | [#507](https://github.com/binglefoundation/bingle_rust/issues/507) |
| Core library | Relays now drop a triangle test 1 or 2 message whose checking endpoint is unusable, such as an Internet Protocol version 6 (IPv6) address or a hostname. They log one warning per message. This prepares relays for endpoint forms that clients do not advertise yet. | [#505](https://github.com/binglefoundation/bingle_rust/issues/505) |
| Local library | With `LocalApiConfig::with_global_block`, messages opened from the Mailbox are dropped if a moderator has blocked the sender. A block stays in place even if the sender later opts out of the DApp. If the chain read fails, the message is let through. | [#504](https://github.com/binglefoundation/bingle_rust/issues/504) |
| CI (continuous integration) | A ready pull request can now target an `integration-*` branch, and the LocalNet integration suite runs on pushes to those branches. Integration branches are only for testing stories together: each story still releases through its own pull request into `staging`. | [#491](https://github.com/binglefoundation/bingle_rust/issues/491) |
| Release process | A MainNet roll now deploys the email gateway after every relay passes its health check. The gateway has the same health check as the relays, and if it fails, the whole roll fails. `roll_relays.sh --check-inventory` now accepts a relative path, and `--help` prints the full header. | [#489](https://github.com/binglefoundation/bingle_rust/issues/489) |
| Release process | The relay CloudFormation templates now allow `logs:CreateLogGroup` on the log-group Amazon Resource Name (ARN). This is needed before CloudWatch Logs changes its rules on 26 April 2027. A roll does not apply it, so existing stacks need `aws cloudformation deploy`, and the MainNet relays are a post-release check. | [#509](https://github.com/binglefoundation/bingle_rust/issues/509) [#512](https://github.com/binglefoundation/bingle_rust/issues/512) |
| Release process | `release.sh` now lists only the post-release checks for changes the release ships. The check for #483 passed and has been removed. | [#506](https://github.com/binglefoundation/bingle_rust/issues/506) [#517](https://github.com/binglefoundation/bingle_rust/issues/517) |

## Upgrading

No code changes are needed, but the new blocklist only takes effect where you turn it on.

- **App (React Native):** to drop messages from senders a moderator has blocked, set `enable_global_block: true` in the bridge config.
- **Rust users of bingle_core and bingle_local:** to drop blocked senders' Mailbox messages, build the config with `LocalApiConfig::with_global_block`. Any relay you run needs its on-chain `allow_relay` flag, or other engines will drop its relay-only messages.
