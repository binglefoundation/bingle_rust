This release adds an email gateway that forwards support messages sent over Bingle as email. It also fixes direct DTLS (Datagram Transport Layer Security) delivery after a phone's network address changes. Nothing breaks, but `--poll-interval 0` now means "read the Mailbox on start only", where it used to fall back to the 20-second default.

## What changed

A user or integrator will notice nine of these changes.

| Area | Change | Issue |
| --- | --- | --- |
| Chat CLI | `--poll-interval 0` now reads the Mailbox once on start and not again. This applies to `chat` and `logclient`. Before, it fell back to the 20-second default. | [#473](https://github.com/binglefoundation/bingle_rust/issues/473) |
| CLI | The new `bingle_cli logclient --state_file <file>` subcommand runs as a registered account. It writes each received text message to stdout as one JSON (JavaScript Object Notation) line, and all logs go to stderr. It reads the Mailbox by default and refuses flags that only affect sending. | [#64](https://github.com/binglefoundation/bingle_rust/issues/64) |
| CLI | `logclient --maildir <dir> --from <address>` writes each message to a Maildir as one email file. Messages are handed on before the state file is saved. A crash therefore can't leave a message saved in history that was never delivered. | [#65](https://github.com/binglefoundation/bingle_rust/issues/65) |
| CLI | `logclient --spam-limit <n>` forwards at most `n` messages per sender per UTC (Coordinated Universal Time) day. Later messages stay in history, readable with `bingle_cli chat`. The counts survive a restart within the day. | [#66](https://github.com/binglefoundation/bingle_rust/issues/66) |
| CLI | `scripts/mailer.sh [--once] <to_email> <maildir>` sends the Maildir through Amazon SES (Simple Email Service), over SMTP (Simple Mail Transfer Protocol) or the SES API. A file is deleted only once SES accepts it. A message rejected for its content moves to `failed/`, and other failures are retried. | [#67](https://github.com/binglefoundation/bingle_rust/issues/67) |
| CLI | `aws/deploy_gateway.sh` deploys the email gateway as an AWS (Amazon Web Services) Fargate service inside an existing relay stack's cluster. State lives on an encrypted file volume, and senders reach the gateway directly over DTLS. The Mailbox is polled every 15 minutes as a backstop. | [#473](https://github.com/binglefoundation/bingle_rust/issues/473) |
| CLI | When `logclient` shuts down, it waits at most 10 seconds for the client lock and then saves anyway. The Mailbox poller stops before its next read, so the node no longer loses messages during shutdown. | [#481](https://github.com/binglefoundation/bingle_rust/issues/481) |
| Core library | A direct session that has been silent for over 60 seconds is replaced with a new handshake before sending. Each retry also starts a new session. A message sent after a phone's NAT (network address translation) mapping changes is now delivered directly, not sent to the Mailbox. | [#488](https://github.com/binglefoundation/bingle_rust/issues/488) |
| Local library | Mailbox `take` transactions are now logged at trace level, like `pop`. The node-capability line moves to debug. This stops two info lines on every receive poll. | [#482](https://github.com/binglefoundation/bingle_rust/issues/482) |
| Tests | A new Detox end-to-end suite tests the sealed state file through the real iOS Keychain and the engine. The suite runs on a reserved "Bingle E2E" simulator, so it can't wipe the Keychain of a development simulator. | [#478](https://github.com/binglefoundation/bingle_rust/issues/478) |

## Upgrading

No code changes are needed.

- App (React Native): update to react-native-bingle-jsi 0.3.38 to get the direct-session fix. A retry whose acknowledgement was lost may now deliver a message twice. The local store already drops the second copy.
- CLI users: if you pass `--poll-interval 0`, the Mailbox is now read only on start. Set a positive interval to keep polling.
- Email gateway operators: redeploy with `aws/deploy_gateway.sh --relay-stack <relay-stack> --redeploy-only` to pick up the shutdown and logging fixes.
