v0.3.40 adds Internet Protocol version 6 (IPv6) support to the Bingle network. It brings a dual-stack UDP (User Datagram Protocol) socket, IPv6 STUN (Session Traversal Utilities for NAT), NAT64 (IPv6-to-IPv4 address translation) and a Mailbox that tries IPv6 first. No change is required, since `--ip-family` defaults to `auto`. The app bridge also gains `getModeratorBlockedContacts()`, so the app can hide messages from a moderator-blocked user that arrived before the block.

## What changed

Eight of these changes are visible to app builders, Rust integrators or relay operators, and the rest are release housekeeping.

| Area | Change | Issue |
|---|---|---|
| App bridge (bingle_jsi) | New `getModeratorBlockedContacts()` lists contacts blocked on chain by a moderator, and returns an empty list when the global blocklist is off. The app can use it to hide messages stored before the block, as it already does for self-service blocks. | [#536](https://github.com/binglefoundation/bingle_rust/issues/536) |
| App bridge (bingle_jsi) | `BingleJsiConfig` has a new `ip_family` option that chooses which address families the engine uses. | [#494](https://github.com/binglefoundation/bingle_rust/issues/494) |
| CLI | New `--ip-family` and `--nat64-prefix` flags. With the default `--ip-family auto`, the relay listens on IPv6 and IPv4 together. `stunservers.txt` is now optional because a built-in STUN server list is used. | [#494](https://github.com/binglefoundation/bingle_rust/issues/494), [#496](https://github.com/binglefoundation/bingle_rust/issues/496) |
| Core library | The UDP socket is now dual-stack and falls back to IPv4 only. IPv4 peers keep their IPv4 identity, including on IPv6-only networks via NAT64. `StartOptions` has a new `ip_family` field, and `network_change()` re-resolves the STUN list. | [#494](https://github.com/binglefoundation/bingle_rust/issues/494), [#496](https://github.com/binglefoundation/bingle_rust/issues/496) |
| Core library | STUN now parses IPv6 mapped addresses. The built-in STUN server replies in the address family of the request. | [#495](https://github.com/binglefoundation/bingle_rust/issues/495) |
| Local library | The Mailbox now tries every address a Sidewinder node advertises: native IPv6 first, then NAT64 IPv6, then IPv4. It uses `sidewinder_ops` and `algo_ops` 0.10.0. | [#497](https://github.com/binglefoundation/bingle_rust/issues/497) |
| Release process | The relay and gateway AWS stacks are now dual-stack: the network, subnet, routes and firewall rules allow IPv6. Each IPv6 rule mirrors an IPv4 rule, and the relay start-up log shows the detected IPv6 address. | [#520](https://github.com/binglefoundation/bingle_rust/issues/520) |
| Release process | The relay and webserver containers now show `--passphrase <set>` in the start-up command they log. The binary still receives the real passphrase. | [#538](https://github.com/binglefoundation/bingle_rust/issues/538) |
| Release process | Two post-release checks passed and were removed from the list: the moderator block on TestNet and the relay log group roles on MainNet. A new note says checks that need `info` log lines require a Debug build of the app. | [#95](https://github.com/binglefoundation/bingle_rust/issues/95), [#376](https://github.com/binglefoundation/bingle_rust/issues/376) |
| Release process | The DApp (decentralised application) schema now records the deployed 0.3.39 program, so the next DApp build compares against what is on chain. | [#490](https://github.com/binglefoundation/bingle_rust/issues/490) |

## Upgrading

No code changes are needed, but some optional steps apply.

- **App (React Native):** to hide earlier messages from moderator-blocked senders, filter the message snapshot with `getModeratorBlockedContacts()`. The bingle_ux_rn #214 change does this. The call may read the chain, so the bridges run it off the main thread.
- **Rust users of bingle_core and bingle_local:** `StartOptions` has a new `ip_family` field. The Mailbox now depends on `sidewinder_ops` and `algo_ops` 0.10.0.
- **CLI users and relay operators:**
  - You can now leave out `stunservers.txt`.
  - A relay roll with `--redeploy-only` or `roll_relays.sh` keeps the previous stack template. Run a full `aws/deploy_relay.sh` deploy to get the dual-stack stack.
  - Amazon Elastic Container Service (ECS) Fargate stacks get IPv6 addresses only if the `dualStackIPv6` account setting is enabled in that region.
  - Amazon Elastic Compute Cloud (EC2) stacks need an instance refresh to get an IPv6 address.
  - Gateway stacks get the change only on a full `aws/deploy_gateway.sh` run, after their relay stack's subnet is dual-stack.
