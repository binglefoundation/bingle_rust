This release adds `getVersions()` to the React Native bridge and fixes two problems in `bingle_cli chat`. Nothing breaks, and no public Rust signature changes. Most readers need two changes: `chat` can now import a registered account from `--passphrase` alone, and the app can read every module's version.

## What changed

Four changes are visible to users or integrators: one in the app bridge, two in the chat command line interface (CLI) and one on the crates.io pages. The rest are internal.

| Area | Change | Issue |
|---|---|---|
| App bridge (bingle_jsi) | `getVersions()` now works from JavaScript on Android and iOS. Before, it failed with `unknown method: getVersions`. It returns version, git SHA, build timestamp and build number for each module, currently `Base` and `JSI`. | [#144](https://github.com/binglefoundation/bingle_rust/issues/144) |
| Chat CLI | On a first run with a new `--state_file`, `bingle_cli chat --passphrase <phrase>` now imports a registered account without `--handle`. The session takes the account's on-chain handle. A `--handle` that differs is still rejected. | [#397](https://github.com/binglefoundation/bingle_rust/issues/397) |
| Chat CLI | Log lines now print above the chat prompt, so your half-typed line stays at the bottom. Empty prompt lines no longer pile up. `chat --plain` turns off the line editor and keeps the old raw output. | [#81](https://github.com/binglefoundation/bingle_rust/issues/81) |
| Crate docs | The install examples in the bingle_core and bingle_local READMEs showed `0.2.8`. They now show the published version. Each release updates them, and publishing fails if a README is stale. | [#197](https://github.com/binglefoundation/bingle_rust/issues/197) |
| Core library | `enrol_sw_client` now calls the app through the same AlgoOps path as related methods. It returns the same transaction ID, and contract rejections are still errors. | [#374](https://github.com/binglefoundation/bingle_rust/issues/374) |
| Core library | A series of clean-ups clears every lint the workspace used to allow, so all Clippy (the Rust linter) lints are back at their defaults. Public signatures are unchanged. New public type aliases, such as `SendViaBingle`, name the same types as before. | [#11](https://github.com/binglefoundation/bingle_rust/issues/11)–[#17](https://github.com/binglefoundation/bingle_rust/issues/17) |
| Tests | The unit test runner now works with macOS's built-in bash 3.2. Before, it stopped before running any tests. The external OpenSSL test now passes with OpenSSL 4 and is skipped with LibreSSL. | [#340](https://github.com/binglefoundation/bingle_rust/issues/340)–[#341](https://github.com/binglefoundation/bingle_rust/issues/341) |
| Tests | The UDP (User Datagram Protocol) network mux tests moved out of the library source into the test tree, following project rules. Production builds do not include the new test hooks. | [#425](https://github.com/binglefoundation/bingle_rust/issues/425) |
| CI (continuous integration) | The Android end-to-end job now caches the native library build. The cache cut the native build from about 505 seconds to about 72 seconds. The publish job no longer saves a cache that only its own re-runs could use. | [#151](https://github.com/binglefoundation/bingle_rust/issues/151) |
| CI (continuous integration) | Before Detox runs, the Android end-to-end job dismisses the lock screen and system dialogs. It also records window focus and device logs. These target a flaky failure whose cause is not yet confirmed. | [#414](https://github.com/binglefoundation/bingle_rust/issues/414) |
| Release process | Release notes are now written on the releaser's machine and reviewed before the release. The version tag and the GitHub Release are created only after publishing succeeds. | [#432](https://github.com/binglefoundation/bingle_rust/issues/432) |
| Release process | The release docs now say the releaser needs the repository admin role. They also say to tick "Allow npm publish" when setting up npm Trusted Publishing. | [#415](https://github.com/binglefoundation/bingle_rust/issues/415) |

## Upgrading

No code changes are needed.

- **App (React Native):** if you call `getVersions()`, call it after init. Before init it rejects with `BINGLE_NOT_INITIALIZED`, but `version()` still works.
- **CLI users:** to import a registered account, `--passphrase` alone is now enough. Pass `--plain` to `chat` if you rely on the old raw output.
