This release lets the app store its own named records in the engine's state file, sealed on iOS and deleted with the account. It breaks Rust code that implements `BingleLocalApi` or `BingleJsiApi`, which must add three new methods. An older engine drops these records the next time it saves.

## What changed

Two of these changes will be noticed by a user or integrator.

| Area | Change | Issue |
| --- | --- | --- |
| App bridge (bingle_jsi) | New methods `appRecord(name)`, `setAppRecord(name, json)` and `removeAppRecord(name)` read, write and delete app records. Setting and removing save before they return. A failed save, such as `StateLocked`, is reported, and the next save writes the record. An invalid name or size returns `InvalidRequest`. | [#471](https://github.com/binglefoundation/bingle_rust/issues/471) |
| Local library | `BingleLocalApi` gains `app_record`, `set_app_record` and `remove_app_record`. They store named JavaScript Object Notation (JSON) values that the engine saves with its state but never reads. Records are sealed when `encrypt_state` is on, and `delete_account` clears them. `validate_app_record` checks the limits: names use `[a-z0-9_.-]` up to 64 characters, and values can be up to 256 KiB. | [#471](https://github.com/binglefoundation/bingle_rust/issues/471) |
| Release process | When `scripts/release.sh` stops on a staging CI job, it now prints the job's link. It also says whether the job is still running or has failed, and what to do before you rerun the script. | [#469](https://github.com/binglefoundation/bingle_rust/issues/469) |

## Upgrading

You only need to change code if you implement `BingleLocalApi` or `BingleJsiApi`.

- **App (React Native):** The bridge methods are new and optional. The state file doesn't change until the app writes a record. If a TestFlight or development install is downgraded to an older engine, that engine drops the records on its next save.
- **Rust users of bingle_core and bingle_local:** If you implement `BingleLocalApi` or `BingleJsiApi`, add `app_record`, `set_app_record` and `remove_app_record`. These traits have no default implementations. `validate_app_record`, `APP_RECORD_NAME_MAX` and `APP_RECORD_VALUE_MAX` are now exported from `bingle_local::api`.
